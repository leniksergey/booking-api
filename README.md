# Restaurant Booking API

REST API для бронирования столика в ресторане. Тестовое задание ОСЬ (Backend Trainee).

**Стек:** Python 3.11+, FastAPI, Pydantic v2, хранение в памяти, pytest.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Swagger: http://127.0.0.1:8000/docs

## Тесты

```bash
python -m pytest -q
```

## Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| POST | `/bookings` | Создать бронь → 201 |
| GET | `/bookings?date=2026-12-15` | Список броней, фильтр по дате необязателен |
| GET | `/bookings/{id}` | Бронь по id, 404 если нет |
| DELETE | `/bookings/{id}` | Отмена: `status=cancelled`, запись остаётся |

Ошибки: `422` — невалидные данные, `404` — `{"detail": "Booking not found"}`, `409` — `{"detail": "Slot is already booked"}`.

## Структура

```
app/
  schemas.py   # модели и валидация входных данных
  service.py   # бизнес-логика, хранилище, правило слота
  routes.py    # HTTP-роуты, без логики
  main.py      # приложение и перевод доменных ошибок в HTTP-коды
tests/
  test_bookings.py
```

## Принятые решения

- **Слои.** Роуты только принимают запрос и вызывают сервис; сервис не знает про HTTP и бросает доменные исключения (`SlotTakenError`, `BookingNotFoundError`), которые `main.py` превращает в 409/404. Так логику можно тестировать и менять независимо от веб-слоя.
- **Валидация в схеме.** Простые правила заданы через `Field`, а диапазон даты (сегодня…+30 дней) и «целый час 12:00–22:00» — через `field_validator`. Невалидные данные отсекаются до сервиса и дают стандартный 422.
- **Слот.** Занятость считается только по броням со статусом `active`, поэтому отменённая бронь освобождает слот, а сама запись сохраняется.
- **Хранилище в памяти** (`dict`) — достаточно для задания; сервис внедряется через `Depends`, что позволяет подменять его в тестах.
- **Отмена идемпотентна:** повторный `DELETE` вернёт ту же отменённую бронь.

## Что доделал бы при наличии времени

- SQLite через SQLAlchemy и миграции (Alembic) вместо хранения в памяти.
- Защиту от гонок при одновременных запросах на один слот (уникальный индекс в БД по активным броням).
- Несколько столов/вместимость вместо единственного слота на время.
- Конфигурацию правил (часы работы, горизонт брони) через настройки, а не константы.
- Расширить тесты и добавить линтер (ruff) и CI.
